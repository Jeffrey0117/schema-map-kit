# 核心地圖(手寫,給工程師規劃與維護時看)
#
# 從全部資料表裡挑出主幹的十幾二十張,按領域分組。只列「規劃時會用到」的欄位,
# 完整欄位在 all-tables.txt。先跑 schema-map probe <表名...> 拿到 json 的 key 與狀態值,再貼進來改。
#
# 讀法
#   name?: type          ? = 可以是空的
#   (-> 表.欄位)          指向另一張表
#   { a | b | c }        正式資料裡實際出現過的值,不保證是全部合法值
#   json 欄位底下縮排的    是裡面的 key
#   fn()                 這件事的判斷寫在哪支程式,不要自己重寫一份
#
# 寫法
#   兩條 ===== 中間那一行是領域標題
#   頂格、小寫的一行是資料表名,後面可以接 # 一句話說明這張表是幹嘛的
#   表底下頂格的 # 是提醒(坑、慣例、容易搞錯的地方)
#
# 改了主幹表的結構、或在 json 裡加了新 key,這份要跟著改。
